# Анонимный мессенджер — деплой на GitHub Pages

GitHub Pages — статический хостинг, серверов там нет. Поэтому сообщения хранит бесплатный Firebase (Firestore), а страница лежит на GitHub.

## 1. Firebase (5 минут)
1. https://console.firebase.google.com → **Add project** (аналитику можно отключить).
2. **Build → Authentication → Get started → Sign-in method → Email/Password → Enable** (только первый переключатель, «Email link» не нужен).
3. **Build → Firestore Database → Create database** (режим production, любой регион).
4. Вкладка **Rules** → вставьте содержимое `firestore.rules` → **Publish**.
5. **Project settings (⚙) → Your apps → значок `</>` (Web)** → зарегистрируйте приложение → скопируйте `firebaseConfig` в файл `firebase-config.js`.

## 2. GitHub Pages
1. Создайте репозиторий (Public), загрузите файлы `index.html`, `firebase-config.js` (`firestore.rules` и `README.md` можно тоже).
2. **Settings → Pages → Deploy from a branch → main / (root) → Save.**
3. Через минуту сайт откроется на `https://ВАШ_НИК.github.io/ИМЯ_РЕПО/`.

## 3. Важно: разрешить домен
Firebase → **Authentication → Settings → Authorized domains → Add domain** → `ВАШ_НИК.github.io`. Без этого вход и регистрация не сработают.

## ⚠️ Если у вас уже был старый проект
Правила `firestore.rules` снова изменились (приватные контакты, просмотр чатов админом, каналы, отметки прочтения). **Обязательно переопубликуйте `firestore.rules` в Firebase Console → Firestore → Rules → Publish**, иначе новые функции (и часть старых) будут падать с ошибкой `permission-denied`.

## Что нового в этой версии (8) — установка как приложение (PWA)
Сайт теперь умеет ставиться на компьютер (Windows/macOS/Linux) и телефон как
обычное приложение — без EXE, без сборки, без Node.js. Добавлены файлы
`manifest.json`, `sw.js` и папка `icons/` с иконкой — просто загрузите их
в репозиторий вместе с остальными файлами (структура папок и имена менять
нельзя, `sw.js` и `manifest.json` должны лежать рядом с `index.html`).

### Как поставить на ПК (Windows) — Chrome или Edge
1. Откройте свой сайт (`https://ваш_ник.github.io/имя_репо/`) в Chrome или Edge.
2. Справа в адресной строке появится значок «Установить» (мониторчик со
   стрелкой) — нажмите его, либо откройте меню (⋮) → «Приложения» →
   «Установить это приложение как…».
3. Готово: на рабочем столе и в меню «Пуск» появится «Мессенджер» — свой
   значок, своё окно без адресной строки браузера, отдельная кнопка на
   панели задач.

### На macOS (Chrome/Edge) и телефоне
То же самое: в Chrome — меню ⋮ → «Установить приложение». На iPhone в
Safari — «Поделиться» → «На экран «Домой»»; на Android в Chrome —
«Установить приложение».

### Важно понимать
- Это не отдельная программа с автономным кодом — приложение всегда
  открывает ваш сайт. Правки на сайте применяются сразу, ничего
  пересобирать не нужно.
- Интернет всё равно обязателен — мессенджер работает через Firebase.
  Если сети нет, откроется сохранённая заглушка вместо белого экрана
  (за это отвечает `sw.js`), но написать или прочитать сообщение без
  сети не получится.
- Если вы сильно поменяете сайт и хотите гарантированно сбросить у всех
  старый кеш — откройте `sw.js` и замените `shell-v1` на `shell-v2`
  (любую новую строку), опубликуйте — старый кеш удалится сам.

### Исправленные баги
- **Ломалась шапка чата.** Аватар в шапке подменялся через `outerHTML` с заменой строки `class="av"`, но генератор выдавал `class="av "` (с пробелом) — `id="hav"` терялся, и при открытии второго чата код падал с `Cannot read properties of null`. Аватар теперь рисуется внутрь постоянного контейнера.

- Кнопка ➕ «в контакты» перехватывалась открытием профиля — порядок обработчиков исправлен.
- Обновления списка пользователей объединяются (debounce 180 мс), чтобы «сердцебиение» статусов не дёргало интерфейс.
- В режиме админ-просмотра шапка брала чат из своего списка и «слепла» после обновления — теперь берёт из админского.
- При открытии чата список сообщений снова всегда прокручивается вниз (сбрасывается флаг `init`).
- Аватар без имени больше не выводит пустую букву; имя в строке контакта берётся через `uname()` (не «undefined»).
- Время выводится в 24-часовом формате независимо от локали браузера.
- Выход из аккаунта и закрытие вкладки помечают вас офлайн сразу.

## Заметки
- `apiKey` в конфиге публичный по дизайну Firebase; доступ защищают правила из `firestore.rules`.
- Ник занимается транзакцией; правила не дают создать занятый ник, писать от чужого имени или читать чужие чаты.
- Бесплатный тариф Spark: ~50 тыс. чтений и 20 тыс. записей в сутки — хватит для небольшой компании.
- Вход по @нику и паролю, работает с любого устройства. Настоящая почта не нужна: внутри ник превращается в служебный адрес `ник@messenger.app`. Из-за этого **восстановить забытый пароль нельзя** — пароль можно только сменить в Настройках, пока вы в аккаунте.
- Фото/видео/файлы хранятся прямо в Firestore-документе (Storage не используется), поэтому есть жёсткий потолок размера (~650 КБ для видео/файлов, фото сжимается автоматически). Для более крупных файлов понадобится подключить Firebase Storage отдельно.
- Данные хранятся у Google и не зашифрованы end-to-end.
- Уведомления работают, пока вкладка открыта (фоновый push потребует Service Worker + FCM).

# Обновление v10 — аккаунты, звонки, без кружков

## 1. Несколько аккаунтов (как в Telegram)

**Настройки → Аккаунты на этом устройстве.** Список сохранённых аккаунтов,
активный отмечен галочкой. Нажатие на строку переключает аккаунт,
**➕ Добавить аккаунт** открывает форму входа для нового ника, ✕ убирает
аккаунт из списка (сам аккаунт при этом не удаляется). Те же аккаунты
показываются на экране входа — можно зайти в один тап.

Переключение перезагружает страницу и заново входит под другим ником:
Firebase Auth держит одну активную сессию на вкладку, поэтому иначе сменить
пользователя нельзя. На глаз это как в Telegram — секунда, и вы в другом
аккаунте.

**Про пароли.** Чтобы переключение работало в один тап, пароли лежат в
localStorage этого устройства в запутанном (XOR + base64) виде. Это защита
от случайного взгляда, а не шифрование: человек с доступом к вашему
разблокированному телефону сможет их достать. На чужом устройстве убирайте
аккаунт через ✕ — пароль сотрётся, и при следующем входе его спросят заново.

Кнопка «Выйти» выходит только из текущего аккаунта и сразу переключает на
следующий сохранённый.

## 2. Кружки удалены

Кнопка ⭕ и запись видео-кружков убраны полностью. Голосовые (🎤) и вложения
(📎) работают как раньше. Старые кружки в переписках не ломаются — они
показываются обычным видео.

## 3. Аудио- и видеозвонки

В шапке личного чата появились **📞** и **🎥**; те же кнопки есть в профиле
пользователя. Входящий звонок показывается поверх всего экрана с рингтоном и
вибрацией — ответить или отклонить. Во время разговора: выключить микрофон,
выключить камеру, положить трубку; идёт таймер. После звонка в переписку
падает строка вроде «📞 Аудиозвонок · 3:14» или «без ответа».

**Как это устроено.** Звук и видео идут напрямую между устройствами по
WebRTC — через Firestore передаётся только «рукопожатие»: кто кому звонит,
offer/answer и ICE-кандидаты. Документ `calls/<id>` живёт секунды и
удаляется сразу после разговора, содержимое разговора на сервер не попадает
и нигде не хранится. Групповых звонков нет — только один на один.

**Обязательно переопубликуйте `firestore.rules`** — там появился блок
`match /calls/{c}`, без него звонки не пройдут (будет `permission-denied`).
Читать и менять документ звонка могут только двое его участников, а позвонить
тому, кто добавил вас в чёрный список, правила не дадут.

**Что нужно, чтобы звонки работали:**

* **HTTPS.** Доступ к микрофону и камере браузер даёт только на защищённом
  соединении (или на `localhost`). GitHub Pages, Netlify, Vercel подходят.
* **Разрешения.** При первом звонке браузер спросит доступ к микрофону и
  камере; если случайно нажать «Блокировать», разрешение надо вернуть в
  настройках сайта.
* **Оба онлайн.** Пуш-уведомлений в закрытом приложении нет — входящий
  звонок виден, только если у собеседника открыта вкладка или PWA.

**Честное ограничение: нет TURN-сервера.** Соединение поднимается через
бесплатные STUN-серверы Google и Cloudflare — они помогают устройствам
найти друг друга напрямую. Этого хватает в большинстве домашних и мобильных
сетей, но при «симметричном NAT» (часто в корпоративных сетях, некоторых
операторах ипубличных Wi-Fi) прямой канал не строится, и звонок покажет
«не удалось соединиться». Лечится только собственным TURN-ретранслятором
(coturn на VPS или платный сервис вроде Twilio/Metered) — его адрес и
логин/пароль дописываются в массив `ICE.iceServers` в `index.html`.
Бесплатного публичного TURN, которому можно доверять, не существует:
через него идёт весь ваш звук и видео.
