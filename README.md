# Анонимный мессенджер — деплой на GitHub Pages

GitHub Pages — статический хостинг, серверов там нет. Поэтому сообщения хранит бесплатный Firebase (Firestore), а страница лежит на GitHub.

## 1. Firebase (5 минут)
1. https://console.firebase.google.com → **Add project** (аналитику можно отключить).
2. **Build → Authentication → Get started → Sign-in method → Email/Password → Enable** (только первый переключатель, «Email link» не нужен).
3. **Build → Firestore Database → Create database** (режим production, любой регион).
4. Вкладка **Rules** → вставьте содержимое `firestore.rules` → **Publish**.
5. **Project settings (⚙) → Your apps → значок `</>` (Web)** → зарегистрируйте приложение → скопируйте `firebaseConfig` в файл `firebase-config.js`.

## 2. GitHub Pages
1. Создайте репозиторий (Public), загрузите файлы `index.html`, `firebase-config.js` (`firestore.rules` и `README.md` можно тоже).
2. **Settings → Pages → Deploy from a branch → main / (root) → Save.**
3. Через минуту сайт откроется на `https://ВАШ_НИК.github.io/ИМЯ_РЕПО/`.

## 3. Важно: разрешить домен
Firebase → **Authentication → Settings → Authorized domains → Add domain** → `ВАШ_НИК.github.io`. Без этого вход и регистрация не сработают.

## ⚠️ Если у вас уже был старый проект
Правила `firestore.rules` снова изменились (приватные контакты, просмотр чатов админом, каналы, отметки прочтения). **Обязательно переопубликуйте `firestore.rules` в Firebase Console → Firestore → Rules → Publish**, иначе новые функции (и часть старых) будут падать с ошибкой `permission-denied`.

## Что нового в этой версии (4)
- **Чёрный список.** Кнопка «🚫 В чёрный список» есть в профиле человека и в меню чата (долгое нажатие или правый клик по строке чата). Заблокированный не может вам написать — это запрещено самими правилами Firestore, а не только интерфейсом, — и вы ему тоже, пока не разблокируете. Его уведомления и звуки не приходят. В шапке чата вместо поля ввода появляется полоса «Пользователь в чёрном списке · Разблокировать». Весь список — в Настройках → «🚫 Чёрный список · N», там же кнопка разблокировки. Список приватный (`users/{u}/priv/blocked`), никто кроме вас его не видит.
- **Удаление диалога.** Долгое нажатие (или правый клик) по чату в списке открывает меню: «Удалить у себя» — чат пропадает только у вас и вернётся, если человек напишет снова; «Удалить у обоих» — сообщения стираются пачками и сам чат удаляется у всех участников, навсегда. Обе команды продублированы в профиле собеседника («🗑 Удалить переписку»). Групп и каналов удаление «у обоих» не касается.
- Удалённый у себя диалог исчезает и из вкладки «Контакты», а если чат удалили с другой стороны — открытая переписка автоматически закрывается.

## Что нового в этой версии (3)
- **Статус онлайн.** Пока вкладка открыта, ваш аккаунт раз в 45 секунд обновляет поле `lastSeen`. У собеседника в шапке чата видно «в сети» (подсвечено) либо «был(а) только что / 12 мин назад / вчера в 21:04 / 3 марта». На аватарах в списке чатов, контактах и профиле горит зелёная точка.
- **Контакты в стиле Telegram.** Во вкладке «Контакты» теперь все, кому вы писали (любой личный чат), плюс добавленные через ➕. Никаких превью сообщений и счётчиков — только фото, имя и статус. Сверху счётчик «N контактов · M в сети». Сортировка: сначала кто в сети, дальше по времени последнего захода. Нажатие на человека открывает его профиль с кнопкой «Написать сообщение».
- **Админ-панель** (вкладка «Админ» видна только у @temqua): счётчики (всего пользователей / в сети / зарегистрировались сегодня / чатов), поиск по @нику и имени, кнопка ✓ — выдать или снять синюю галочку, кнопка SCAM — поставить или снять метку мошенника. Вторая подвкладка «Чаты» — прежний просмотр чужих переписок только для чтения. Те же две кнопки продублированы в профиле пользователя, когда его открывает @temqua.
- Галочка и метка SCAM показываются везде: в списке чатов, контактах, шапке чата, профиле, именах в группах и в ответах на сообщения. В профиле SCAM-аккаунта дополнительно выводится красное предупреждение.
- @nayk получает галочку автоматически при первом входе @temqua (дальше её можно снять кнопкой в панели).

### Исправленные баги
- **Ломалась шапка чата.** Аватар в шапке подменялся через `outerHTML` с заменой строки `class="av"`, но генератор выдавал `class="av "` (с пробелом) — `id="hav"` терялся, и при открытии второго чата код падал с `Cannot read properties of null`. Аватар теперь рисуется внутрь постоянного контейнера.
- Ввод в настройках и в поиске админ-панели больше не сбрасывается: список не перерисовывается, пока в нём сфокусировано поле (раньше любое обновление чужого профиля стирало недописанное имя). Заодно сохраняется позиция прокрутки.
- Кнопка ➕ «в контакты» перехватывалась открытием профиля — порядок обработчиков исправлен.
- Обновления списка пользователей объединяются (debounce 180 мс), чтобы «сердцебиение» статусов не дёргало интерфейс.
- В режиме админ-просмотра шапка брала чат из своего списка и «слепла» после обновления — теперь берёт из админского.
- При открытии чата список сообщений снова всегда прокручивается вниз (сбрасывается флаг `init`).
- Аватар без имени больше не выводит пустую букву; имя в строке контакта берётся через `uname()` (не «undefined»).
- Время выводится в 24-часовом формате независимо от локали браузера.
- Выход из аккаунта и закрытие вкладки помечают вас офлайн сразу.

- Каналы: новый тип чата, где писать может только создатель (и назначенные им администраторы), остальные участники только читают. Управление администраторами — в профиле канала у владельца.

## Заметки
- `apiKey` в конфиге публичный по дизайну Firebase; доступ защищают правила из `firestore.rules`.
- Ник занимается транзакцией; правила не дают создать занятый ник, писать от чужого имени или читать чужие чаты.
- Бесплатный тариф Spark: ~50 тыс. чтений и 20 тыс. записей в сутки — хватит для небольшой компании.
- Вход по @нику и паролю, работает с любого устройства. Настоящая почта не нужна: внутри ник превращается в служебный адрес `ник@messenger.app`. Из-за этого **восстановить забытый пароль нельзя** — пароль можно только сменить в Настройках, пока вы в аккаунте.
- Фото/видео/файлы хранятся прямо в Firestore-документе (Storage не используется), поэтому есть жёсткий потолок размера (~650 КБ для видео/файлов, фото сжимается автоматически). Для более крупных файлов понадобится подключить Firebase Storage отдельно.
- Данные хранятся у Google и не зашифрованы end-to-end.
- Уведомления работают, пока вкладка открыта (фоновый push потребует Service Worker + FCM).
