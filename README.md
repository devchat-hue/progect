# Push-уведомления и фоновые звонки — разворачивание

Сам сайт (index.html) работает и без этого шага: сообщения и звонки видны,
пока вкладка открыта. Но чтобы уведомление пришло, когда вкладка/браузер
**закрыты**, нужна серверная часть — она лежит в этой папке и один раз
разворачивается через Firebase CLI. Дальше ничего вручную запускать не
придётся — функции работают сами.

## Что для этого нужно
- Node.js (18 или новее) — только на вашем компьютере, для разворачивания.
  На самом сайте/у пользователей Node.js не нужен.
- Тот же Firebase-проект, что уже используется в `firebase-config.js`
  (`chat2-3f11a` — уже прописан в `.firebaserc`, менять не нужно, если это
  ваш проект).
- **План Blaze** (pay-as-you-go) вместо бесплатного Spark — Cloud Functions
  требуют его для разворачивания в принципе, даже если вы останетесь в
  пределах бесплатных лимитов. Смените план в Firebase Console → значок
  ⚙️ рядом с названием проекта → Usage and billing → Details & settings.
  Отправка push через FCM бесплатна и в лимиты Blaze почти никогда не
  упирается при обычной нагрузке мессенджера.

## Шаги
1. Установите Firebase CLI (один раз, глобально):
   ```
   npm install -g firebase-tools
   ```
2. Войдите в свой аккаунт Google:
   ```
   firebase login
   ```
3. В папке `functions/` установите зависимости:
   ```
   cd functions
   npm install
   cd ..
   ```
4. Разверните функции (из корня проекта, где лежит `firebase.json`):
   ```
   firebase deploy --only functions
   ```
   Через минуту-две в выводе появятся `onNewMessage` и `onCallRinging` —
   значит всё развернулось.

## Получить VAPID-ключ (обязательно, иначе push не запросится у браузера)
1. Firebase Console → ⚙️ Project settings → вкладка **Cloud Messaging**.
2. Раздел **Web configuration → Web Push certificates** → **Generate key pair**.
3. Скопируйте строку ключа и вставьте в `firebase-config.js`:
   ```js
   window.FIREBASE_VAPID_KEY = "тут_ваш_ключ";
   ```
4. Загрузите обновлённый `firebase-config.js` туда же, где лежит сайт
   (GitHub Pages и т.п.).

## Проверка
1. Откройте сайт, зайдите в Настройки → включите «Уведомления» → разрешите
   в браузере.
2. С другого аккаунта (другой браузер/вкладка инкогнито/телефон) напишите
   сообщение или позвоните.
3. Сверните/закройте первую вкладку — уведомление должно прийти как обычное
   системное уведомление, со звуком и (для звонка) кнопками «Ответить» /
   «Отклонить».

## Важные ограничения (платформенные, не Firebase)
- **iOS/Safari**: push для сайтов работает только если сайт добавлен на
  экран «Домой» (Safari → «Поделиться» → «На экран «Домой»») и только на
  iOS 16.4+. Обычная открытая вкладка Safari push в фоне получать не может —
  это ограничение самого iOS, обойти его нельзя.
- **Картинка в уведомлении**: у сообщений с фото в самом уведомлении будет
  подпись «🖼 Фото», а не превью фотографии — потому что фото в этом
  мессенджере хранятся как base64 прямо в Firestore (без Firebase Storage),
  а push поддерживает картинку только по прямой https-ссылке. Если захотите
  показывать реальные превью — понадобится Firebase Storage и загрузка туда
  копии фото при отправке.
- **«Ответить»/«Отклонить» на звонок из уведомления**: нажатие открывает
  (или переключает на) вкладку с сайтом — экран входящего звонка там
  появится сам (он уже слушает `calls/*` через `onSnapshot`), дальше нажимаете
  обычную кнопку приёма/отклонения. Полностью принять WebRTC-звонок, не
  открывая страницу, невозможно ни в одном браузере — сам разговор идёт
  через `RTCPeerConnection`, которому нужна открытая страница.
- Если через некоторое время в консоли Firebase функции начнут падать с
  ошибкой про квоты — значит нагрузка выросла настолько, что вышла за
  бесплатный лимит; тогда посмотрите Usage and billing, но для обычного
  чата это маловероятно.
